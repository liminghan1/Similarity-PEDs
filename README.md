# Structure-to-Safety

**Multimodal Computational Pharmacology of Anabolic-Androgenic Steroids**

Structure-to-Safety is a multimodal computational pharmacology project investigating whether molecular and
receptor-level similarities among anabolic-androgenic steroids (AAS) correspond to similarities in their
real-world adverse-event **reporting** profiles, as captured in the FDA Adverse Event Reporting System
(FAERS/openFDA).

This is a research-first project. The primary artifacts are a reproducible data pipeline, a pre-specified and
scientifically defensible analysis, documented inclusion/exclusion criteria, statistical results, sensitivity
analyses, publication-quality figures, and a research report — **not** the web dashboard, which exists only to
explore results that have already been produced by the pipeline below.

## Research questions

> Are anabolic-androgenic steroids with similar molecular structures and receptor pharmacology associated with
> similar real-world adverse-event reporting profiles?

This is broken into four specific aims (molecular/pharmacological phenotyping, FAERS safety phenotyping,
structure/pharmacology-to-safety matrix association, and therapeutic-use-vs-misuse comparison) and four
pre-registered hypotheses. See [`research/hypotheses.md`](research/hypotheses.md) and
[`research/analysis_plan.md`](research/analysis_plan.md).

**This project does not build cycle builders, dose calculators, "safest/best steroid" rankings, or stacking
recommendations, and does not design novel compounds.** See Sec. 36 of the original project brief (also
reflected in `TODO.md`) for the explicit scope boundary.

## What FAERS can and cannot tell us

FAERS is a spontaneous, voluntary reporting system. It **cannot** establish incidence, prevalence, absolute
risk, or causation. Every statistic derived from it in this project is described as a *reporting association*
or *disproportionality signal*, never as a risk or causal effect. See the Limitations section of
[`research/exclusion_rules.md`](research/exclusion_rules.md) and the (forthcoming) `reports/research_report.md`
for the full discussion of confounding (age, sex, indication, polypharmacy, other PED exposure, reporting bias,
product adulteration, lack of an exposure denominator, and more).

## Data sources

- **PubChem** (PUG REST) — compound identifiers, canonical/isomeric structure, molecular formula, basic
  chemical properties.
- **ChEMBL** — receptor bioactivity (Ki/IC50/EC50/Kd), assay metadata, target/organism/confidence.
- **BindingDB** (optional, complementary) — measured protein-ligand interactions, provenance kept separate from
  ChEMBL.
- **FDA FAERS / openFDA** — adverse-event reports, reactions, indications, seriousness, outcomes, co-reported
  medications.

No API key is required for PubChem, ChEMBL, or openFDA at low request volumes; an optional openFDA key raises
the rate limit (see `.env.example`).

## Reproducibility

- Python dependencies are pinned via `uv` (`pyproject.toml` + `uv.lock`, committed).
- PostgreSQL is provisioned via `docker-compose.yml`; schema changes are managed with Alembic migrations
  (`backend/alembic/`).
- All analyses fix and record a random seed (default `42`, see `.env.example`), and every derived dataset is
  written with a provenance manifest (`artifacts/manifests/`) recording source versions, the Git commit, and
  filtering rules applied.

### Setup

```bash
cp .env.example .env
make venv        # uv sync --extra dev
make db-up       # start PostgreSQL via docker-compose
make db-migrate  # apply Alembic migrations
make test        # run the backend test suite
make api         # run the FastAPI dev server (http://127.0.0.1:8000/docs)
```

## Limitations (summary)

- Small compound cohort (≤ ~10 canonical parents to start) limits statistical power for multivariate analyses.
- Receptor bioactivity coverage is expected to be sparse and heterogeneous across assay types/organisms/formats
  — this project never pools Ki/IC50/EC50/Kd as equivalent, and documents an explicit missing-data strategy
  rather than imputing silently.
- FAERS reporting is voluntary, subject to stimulated/publicity reporting, duplicate/follow-up reports, and has
  no reliable exposure denominator — disproportionality signals are reporting associations, not risk estimates.
- Custom adverse-event categories used in this project (`research/ae_categories.csv`) are **research-defined**,
  not an official licensed MedDRA System Organ Class hierarchy.

Full discussion: `research/exclusion_rules.md`, and (once populated) `reports/research_report.md` §Limitations.
